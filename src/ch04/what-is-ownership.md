# 소유권(Ownership)이 뭔가요?

> 참고: [The Rust Programming Language 한국어 번역 2판 (rinthel)](https://rinthel.github.io/rust-lang-book-ko/ch04-01-what-is-ownership.html), [최신 2021 에디션 번역본 (doc.rust-kr.org)](https://doc.rust-kr.org/ch04-01-what-is-ownership.html), [원문 (doc.rust-lang.org)](https://doc.rust-lang.org/book/ch04-01-what-is-ownership.html)
---

## 0. 한 줄 요약

| | Java | Rust |
|---|---|---|
| 메모리 해제 주체 | GC가 런타임에 알아서 | **컴파일러가 정한 규칙**에 따라, 변수가 스코프를 벗어나는 순간 |
| 해제 시점 | 예측 불가 (GC가 돌 때) | 결정적 (`}`를 만나는 순간) |
| 런타임 비용 | GC 스레드, Stop-the-world | 없음 (검사는 전부 컴파일 타임) |
| `b = a` (객체) | 참조 복사, `a`/`b` 둘 다 사용 가능 | 소유권 **이동(move)**, `a`는 더 이상 사용 불가 |

메모리를 관리하는 방식은 크게 세 가지입니다.

1. **GC 방식** — Java, Go, Python. 안 쓰는 메모리를 런타임이 주기적으로 찾아 치움.
2. **수동 방식** — C, C++. 프로그래머가 `malloc`/`free`를 직접 짝지어 호출.
3. **소유권 방식** — Rust. 컴파일러가 소유권 규칙을 검사하고, 규칙을 어기면 컴파일 자체가 안 됨. 해제 코드는 컴파일러가 알맞은 위치에 넣어 줌.

자바 개발자 입장에서 Rust의 소유권은 **"GC 없이도 메모리 안전성을 얻기 위해, 객체마다 주인을 딱 한 명만 두는 규칙"** 이라고 생각하면 됩니다.

## 1. 스택과 힙 — 자바에서도 이미 쓰고 있던 개념

자바에서도 내부적으로는 똑같이 동작합니다. 다만 GC가 있어서 의식할 일이 적었을 뿐입니다.

```java
void foo() {
    int count = 10;                 // 스택: 지역 변수(원시 타입) 값 자체
    User user = new User("kim");    // 스택: user 참조(주소) / 힙: User 객체
}
```

| | 스택 (Stack) | 힙 (Heap) |
|---|---|---|
| 구조 | 후입선출(LIFO), 접시 쌓기 | 빈 공간을 찾아 할당 |
| 크기 | 컴파일 타임에 고정된 크기만 | 크기가 가변이거나 미리 모르는 데이터 |
| 속도 | 빠름 (항상 맨 위에 push/pop) | 상대적으로 느림 (공간 탐색 + 포인터 따라가기) |
| 자바 예시 | `int`, `boolean`, 참조 변수 자체 | `new`로 만든 모든 객체 |
| 러스트 예시 | `i32`, `bool`, `f64`, `char`, 포인터 | `String`, `Vec<T>`, `Box<T>`의 실제 데이터 |

**소유권이 존재하는 이유는 결국 힙 데이터 관리**입니다. 누가 힙의 어떤 데이터를 쓰고 있는지 추적하고, 중복을 줄이고, 안 쓰는 데이터를 치우는 일을 자바는 GC가, 러스트는 소유권 규칙이 맡습니다.

---

## 2. 소유권 규칙 3가지

이 세 줄이 이 장의 전부입니다.

1. 러스트의 각 값은 **소유자(owner)** 가 있다.
2. 소유자는 **동시에 하나만** 존재할 수 있다.
3. 소유자가 스코프를 벗어나면 값은 **버려진다(dropped)**.

자바와 비교하면 2번이 결정적인 차이입니다. 자바는 하나의 객체를 여러 참조가 마음대로 가리킬 수 있고, 마지막 참조가 사라지면 GC가 치웁니다. 러스트는 "주인은 한 명"이라는 제약을 두는 대신 GC가 필요 없어집니다.

## 3. 변수의 스코프

```rust
{                      // s는 아직 선언 전이라 유효하지 않음
    let s = "hello";   // 여기서부터 s가 유효
    // s 사용
}                      // 스코프 종료 → s는 더 이상 유효하지 않음
```

여기까지는 자바의 지역 변수 블록 스코프와 똑같습니다.

---

## 4. `String` 타입 — 자바의 `String`이 아니라 `StringBuilder`에 가깝다

러스트에는 문자열 타입이 두 가지 있습니다.

| 러스트 | 특징 | 자바로 비유하면 |
|---|---|---|
| 문자열 리터럴 `"hello"` (`&str`) | 불변, 실행 파일에 하드코딩 | 상수 풀에 있는 `"hello"` 리터럴 |
| `String::from("hello")` | 가변, 힙에 할당, 크기가 늘어날 수 있음 | `StringBuilder` |

```rust
let mut s = String::from("hello");
s.push_str(", world!");   // 자바의 sb.append(", world!")
println!("{}", s);        // hello, world!
```

`String::from`의 `::`는 자바의 정적 메서드 호출 `String.valueOf(...)`의 `.`과 비슷한 역할입니다. `String` 타입에 속한 `from` 함수라는 뜻입니다.

> 주의: 자바의 `String`은 불변 객체라서, 러스트의 `String`과 이름은 같지만 성격이 다릅니다.

## 5. 메모리와 할당 — `drop`은 "자동으로 호출되는 close()"

힙에 데이터를 두려면 두 가지가 필요합니다.

1. 런타임에 메모리를 **요청**한다 → `String::from`이 알아서 함 (자바의 `new`와 같음)
2. 다 쓰면 메모리를 **반납**한다 → 여기서 언어마다 갈림

| 언어 | 반납 방식 | 문제 |
|---|---|---|
| C | 직접 `free()` | 잊으면 누수, 너무 빨리 하면 dangling, 두 번 하면 double free |
| Java | GC | 해제 시점 예측 불가, GC 오버헤드 |
| Rust | 스코프 끝(`}`)에서 `drop` 자동 호출 | 규칙을 지켜야 컴파일됨 |

```rust
{
    let s = String::from("hello"); // s 유효
    // s 사용
}                                  // 여기서 러스트가 자동으로 drop(s) 호출 → 힙 메모리 해제
```

자바 개발자에게 가장 가까운 개념은 **try-with-resources**입니다.

```java
try (var in = new FileInputStream("a.txt")) {
    // in 사용
}   // 블록을 벗어나면 in.close()가 자동 호출
```

러스트는 이걸 **모든 값에, 문법 없이, 항상** 적용한다고 보면 됩니다. `finalize()`처럼 "언젠가 GC가 불러 주겠지"가 아니라, `}`에서 정확히 호출됩니다. (C++에서는 이 패턴을 RAII라고 부릅니다.)

## 6. 이동(Move) — 자바 개발자가 가장 헷갈리는 부분

### 6-1. 정수: 그냥 복사

```rust
let x = 5;
let y = x;   // 5가 복사됨. x, y 둘 다 5
```

자바의 `int y = x;`와 완전히 같습니다.

### 6-2. `String`: 자바라면 이렇게 됐을 것

```java
String s1 = new String("hello");
String s2 = s1;          // 참조(주소)만 복사
System.out.println(s1);  // OK. s1, s2가 같은 객체를 가리킴
```

자바는 두 참조가 같은 힙 객체를 공유해도 문제가 없습니다. 아무도 안 가리키게 되면 GC가 한 번만 치우니까요.

### 6-3. 러스트에서는?

```rust
let s1 = String::from("hello");
let s2 = s1;
```

`String`은 스택에 3개의 값을 가집니다: **힙을 가리키는 포인터, 길이(len), 용량(capacity)**.

```
   s1 (스택)                     힙
┌──────────┬───────┐        ┌───┬───┐
│ ptr      │   ────┼──────▶ │ 0 │ h │
│ len      │   5   │        │ 1 │ e │
│ capacity │   5   │        │ 2 │ l │
└──────────┴───────┘        │ 3 │ l │
                            │ 4 │ o │
                            └───┴───┘
```

- **길이**: 현재 내용이 쓰고 있는 바이트 수
- **용량**: 할당자에게 받은 전체 바이트 수 (자바 `ArrayList`의 size와 내부 배열 크기 차이와 비슷)

`s2 = s1`을 하면 **스택에 있는 ptr, len, capacity만 복사**되고, 힙 데이터는 복사되지 않습니다. 여기까지는 자바의 참조 복사와 같습니다.

```
   s1 (스택)                     힙
┌──────────┬───────┐        ┌───┬───┐
│ ptr      │   ────┼──────▶ │ 0 │ h │
│ len      │   5   │   ┌──▶ │ 1 │ e │
│ capacity │   5   │   │    │ 2 │ l │
└──────────┴───────┘   │    │ 3 │ l │
   s2 (스택)           │    │ 4 │ o │
┌──────────┬───────┐   │    └───┴───┘
│ ptr      │   ────┼───┘
│ len      │   5   │
│ capacity │   5   │
└──────────┴───────┘
```

### 6-4. 문제: Double Free

러스트는 GC가 없고, 스코프를 벗어나면 `drop`을 호출한다고 했습니다. 그런데 위 그림처럼 둘이 같은 힙을 가리킨 채로 `s1`, `s2`가 모두 스코프를 벗어나면 **같은 메모리를 두 번 해제**하게 됩니다. 이것이 **double free** 오류이고, 메모리 손상과 보안 취약점의 원인이 됩니다.

### 6-5. 러스트의 해결: `s1`을 무효화

메모리 안전성(memory safety)을 보장하기 위해, 러스트는 `let s2 = s1;` 이후 **`s1`이 더 이상 유효하지 않다고 간주**합니다. 그래서 `s1`이 스코프를 벗어나도 아무것도 해제하지 않고, 해제는 유효한 `s2`가 스코프를 벗어날 때 **딱 한 번만** 일어납니다.

```
   s1 (무효화됨)                  힙
┌──────────┬───────┐        ┌───┬───┐
│ ░░░░░░░░ │ ░░░░░ │        │ 0 │ h │
│ ░░░░░░░░ │ ░░░░░ │   ┌──▶ │ 1 │ e │
└──────────┴───────┘   │    │ 2 │ l │
   s2 (유일한 소유자)  │    │ 3 │ l │
┌──────────┬───────┐   │    │ 4 │ o │
│ ptr      │   ────┼───┘    └───┴───┘
│ len      │   5   │
│ capacity │   5   │
└──────────┴───────┘
```

무효화된 `s1`을 쓰려고 하면 **컴파일 에러**가 납니다.

```rust
let s1 = String::from("hello");
let s2 = s1;

println!("{}, world!", s1);
```

```text
error[E0382]: borrow of moved value: `s1`
 --> src/main.rs:5:28
  |
2 |     let s1 = String::from("hello");
  |         -- move occurs because `s1` has type `String`, which does not implement the `Copy` trait
3 |     let s2 = s1;
  |              -- value moved here
4 |
5 |     println!("{}, world!", s1);
  |                            ^^ value borrowed here after move
  |
help: consider cloning the value if the performance cost is acceptable
  |
3 |     let s2 = s1.clone();
  |                ++++++++
```

에러 메시지를 읽는 법:
- `value moved here` → 3번째 줄에서 소유권이 `s2`로 넘어감
- `value borrowed here after move` → 넘겨준 뒤에 `s1`을 또 쓰려고 함
- `does not implement the Copy trait` → `String`은 자동 복사 대상이 아니라서 이동이 일어남

### 6-6. 얕은 복사가 아니라 "이동"

자바식 용어로 보면 포인터·길이·용량만 복사하는 건 **얕은 복사(shallow copy)** 처럼 보입니다. 하지만 러스트는 **원래 변수까지 무효화**하기 때문에 이를 얕은 복사가 아니라 **이동(move)** 이라고 부르고, "`s1`이 `s2`로 이동되었다"고 말합니다.

| | 힙 데이터 복사? | 원본 변수 사용 가능? |
|---|---|---|
| 자바의 참조 대입 | X | O |
| 얕은 복사 | X | O |
| 깊은 복사 | O | O |
| **러스트 move** | **X** | **X** |

그리고 중요한 설계 원칙 하나: **러스트는 절대 자동으로 깊은 복사를 하지 않습니다.** 따라서 러스트가 자동으로 하는 복사는 항상 비용이 싸다고 믿어도 됩니다.

## 7. 클론(Clone) — 깊은 복사를 원할 때

힙 데이터까지 복사하고 싶으면 `clone()`을 **명시적으로** 호출합니다.

```rust
let s1 = String::from("hello");
let s2 = s1.clone();   // 힙 데이터까지 복사

println!("s1 = {}, s2 = {}", s1, s2);  // 둘 다 사용 가능
```

```
   s1 (스택)                 힙
┌──────────┬─────┐       ┌─────────┐
│ ptr      │ ────┼─────▶ │ "hello" │
│ len / cap│ 5/5 │       └─────────┘
└──────────┴─────┘
   s2 (스택)
┌──────────┬─────┐       ┌─────────┐
│ ptr      │ ────┼─────▶ │ "hello" │   ← 별도의 복사본
│ len / cap│ 5/5 │       └─────────┘
└──────────┴─────┘
```

코드에서 `.clone()`이 보이면 "여기서 비용이 드는 작업이 일어날 수 있다"는 **시각적 신호**로 받아들이면 됩니다.

> 자바와의 차이: 자바의 `Object.clone()`은 기본이 **얕은 복사**라서 내부 필드 객체는 공유됩니다. 러스트 `String`의 `clone()`은 힙 내용까지 새로 만드는 깊은 복사입니다. 이름은 같아도 기대하는 동작이 다르니 주의하세요.

## 8. 스택 전용 데이터: 복사(Copy) — 자바의 원시 타입과 같다

```rust
let x = 5;
let y = x;

println!("x = {}, y = {}", x, y);   // 정상 동작
```

`clone()`도 안 했는데 `x`가 여전히 유효합니다. 정수처럼 **컴파일 타임에 크기가 정해진 타입은 전부 스택에 저장**되고 복사가 매우 싸기 때문에, 굳이 `x`를 무효화할 이유가 없습니다. 이런 타입에서는 얕은 복사와 깊은 복사의 구분 자체가 의미가 없습니다.

러스트는 이런 타입에 **`Copy` 트레이트**를 붙여 둡니다. (트레이트는 자바의 인터페이스와 비슷한 개념이고, 10장에서 다룹니다.) `Copy`가 구현된 타입은 대입해도 이동되지 않고 복사되어, 원래 변수를 계속 쓸 수 있습니다.

**`Copy` 가능한 대표 타입** — 자바의 원시 타입과 거의 일치합니다.

| 러스트 | 자바 대응 |
|---|---|
| 모든 정수형 (`i32`, `u32`, `i64` …) | `int`, `long` … |
| `bool` | `boolean` |
| 모든 부동소수점 (`f32`, `f64`) | `float`, `double` |
| `char` | `char` (단, 러스트 `char`는 4바이트 유니코드 스칼라 값) |
| `Copy` 타입으로만 구성된 튜플 `(i32, i32)` | — |

- `(i32, String)`처럼 `Copy`가 아닌 타입이 하나라도 섞이면 `Copy`가 아닙니다.
- 일반 규칙: **단순한 스칼라 값의 묶음은 `Copy` 가능, 힙 할당이 필요하거나 자원을 다루는 타입은 불가능.**
- 타입 자체나 그 일부가 `Drop` 트레이트를 구현했다면 `Copy`를 붙일 수 없습니다. "스코프를 벗어날 때 특별한 정리 작업이 필요한 타입"을 몰래 복사하면 정리가 중복되기 때문입니다.

## 9. 소유권과 함수 — 메서드에 넘기면 돌려받지 못한다

자바는 메서드에 객체를 넘겨도 호출한 쪽에서 계속 쓸 수 있습니다.

```java
String s = "hello";
takesString(s);
System.out.println(s);   // OK
```

러스트에서 함수에 값을 넘기는 것은 **대입과 똑같이 동작**합니다. 즉 이동 또는 복사가 일어납니다.

```rust
fn main() {
    let s = String::from("hello");  // s가 스코프에 들어옴

    takes_ownership(s);             // s의 값이 함수로 이동
                                    // → 여기부터 s는 유효하지 않음

    let x = 5;                      // x가 스코프에 들어옴

    makes_copy(x);                  // i32는 Copy라서 복사됨
                                    // → x는 계속 사용 가능

} // x가 스코프를 벗어남. s도 벗어나지만 이미 이동됐으므로 아무 일도 없음

fn takes_ownership(some_string: String) { // some_string이 소유권을 가짐
    println!("{}", some_string);
} // some_string이 스코프를 벗어나며 drop 호출 → 메모리 해제

fn makes_copy(some_integer: i32) {
    println!("{}", some_integer);
} // some_integer가 스코프를 벗어남. 특별한 일 없음
```

`takes_ownership(s)` 이후에 `s`를 쓰면 컴파일 에러가 납니다. 자바 감각으로는 "메서드에 넘긴 객체를 메서드가 가져가 버리고, 메서드가 끝날 때 폐기한다"고 이해하면 됩니다.

## 10. 반환 값과 스코프 — 소유권은 반환으로도 이동한다

```rust
fn main() {
    let s1 = gives_ownership();        // 반환값의 소유권이 s1으로 이동

    let s2 = String::from("hello");    // s2가 스코프에 들어옴

    let s3 = takes_and_gives_back(s2); // s2는 함수로 이동했다가,
                                       // 반환값으로 s3에 이동
} // s3: drop 호출 / s2: 이미 이동됐으므로 아무 일 없음 / s1: drop 호출

fn gives_ownership() -> String {
    let some_string = String::from("yours");
    some_string                        // 호출한 쪽으로 소유권 이동
}

fn takes_and_gives_back(a_string: String) -> String {
    a_string                           // 받은 걸 그대로 돌려줌 (소유권 반환)
}
```

규칙은 항상 같습니다.

- 값을 다른 변수에 대입하면 → **이동**
- 힙 데이터를 가진 변수가 스코프를 벗어나면 → 다른 변수로 이동되지 않은 한 **`drop`으로 정리**

### 그런데 매번 돌려받는 건 번거롭다

함수에 값을 넘긴 뒤 다시 쓰고 싶다면, 결과와 함께 원래 값도 반환받아야 합니다.

```rust
fn main() {
    let s1 = String::from("hello");
    let (s2, len) = calculate_length(s1);   // 튜플로 둘 다 돌려받음
    println!("The length of '{}' is {}.", s2, len);
}

fn calculate_length(s: String) -> (String, usize) {
    let length = s.len();
    (s, length)
}
```

자바로 치면 길이 하나 구하려고 `record Result(String s, int len)`을 만들어 원본까지 같이 반환하는 꼴이라 너무 번거롭습니다. 그래서 러스트는 **소유권을 넘기지 않고 값을 "빌려주는"** 기능인 **참조자(reference, `&`)** 를 제공합니다. 다음 장(4.2 참조자와 빌림)의 주제입니다.

## 11. 자바 개발자를 위한 최종 비교표

| 상황 | Java | Rust |
|---|---|---|
| `b = a` (객체) | 참조 공유, 둘 다 사용 | `a` → `b`로 **이동**, `a` 사용 불가 |
| `b = a` (원시 타입 / `Copy`) | 값 복사 | 값 복사 (`Copy` 트레이트) |
| 깊은 복사 | 직접 구현 (`clone()`은 기본 얕은 복사) | `.clone()` 명시적 호출 |
| 메서드에 객체 전달 | 참조 값 전달, 호출자도 계속 사용 | **소유권 이동**, 호출자는 사용 불가 |
| 사용 안 하는 객체 정리 | GC가 나중에 | 소유자가 스코프 벗어날 때 즉시 `drop` |
| 자원 정리 문법 | `try-with-resources` + `AutoCloseable` | 모든 값에 자동 적용 (`Drop` 트레이트) |
| 잘못된 사용 감지 | 런타임 (NPE, 동시성 버그 등) | **컴파일 타임** |

### 핵심 문장 정리

- 러스트의 각 값은 소유자가 **딱 하나**이고, 소유자가 스코프를 벗어나면 값이 정리된다.
- 힙 데이터를 가진 타입(`String` 등)을 대입하거나 함수에 넘기면 **이동**이 일어나고, 원래 변수는 무효화된다.
- 이동은 double free를 컴파일 타임에 원천 차단하기 위한 장치다.
- 깊은 복사는 자동으로 일어나지 않는다. 필요하면 `.clone()`을 직접 쓴다.
- 스택 전용 타입(정수, `bool`, 부동소수점, `char` 등)은 `Copy`라서 대입 후에도 원본을 쓸 수 있다.
- 매번 소유권을 주고받는 불편함은 다음 장의 **참조자와 빌림**으로 해결한다.
